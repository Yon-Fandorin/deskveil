# 개발 메모

## 책임과 수명

- `AppDelegate`가 입력 차단 세션·설정·전원·밝기·macOS 잠금 전환을 조율합니다. 화면 코드는 상태 표시와 사용자 요청 전달을 담당합니다.
- `InputFilter`는 전용 스레드에서 이벤트와 눌림 상태를 처리합니다. 콜백에서 AppKit·프로세스 실행·파일 기록·전원 API를 호출하지 않습니다. UI 요청은 메인 큐에 전달합니다.
- 밝기 제어와 화면 전환 덮개는 각각 별도의 보조 프로세스에서 처리합니다. 부모 종료·파이프 단절·하트비트 중단 시 독립적으로 복구합니다. 오래된 자식의 종료 콜백이 새 자식을 정리하지 않도록 프로세스 신원을 확인합니다. 파이프 읽기 핸들러는 자식 실행 성공 뒤 설치해 실행 실패 시 참조 순환과 파일 핸들 누수를 피합니다. 응답 파이프가 먼저 닫히더라도 마지막 밝기 복원을 실행할 수 있도록 SIGPIPE를 무시합니다. 앱 재시작은 이전 보조 프로세스의 종료를 확인한 뒤 새 인스턴스를 엽니다.
- 운영 업데이트는 `Tools/update-app.py`로 적용합니다. `DeferredUpdateGate`는 같은 사용자의 대기 요청만 받고 실행 경로나 설치 명령을 받지 않습니다. 적용 가능 여부는 `AppDelegate`가 메인 스레드에서 판단합니다. 차단·화면 전환·복원·개별 화면 감춤·단축키 녹음·덮개 정리가 끝나기 전에는 종료하지 않습니다. 정리를 시작하면 새로운 차단·녹음·보조 도구 설치를 막습니다.
- 업데이터는 서명·신원·버전·전체 파일 manifest를 확인한 후보만 보관합니다. 준비 응답 뒤 빌드 잠금을 확보해 종료를 승인하고, 실제 프로세스 종료를 확인한 뒤 복사본을 교체합니다. 차단 해제를 기다리는 동안에는 빌드 잠금을 점유하지 않습니다. 강제 종료로 조건을 우회하지 않습니다. 승인 전 취소나 연결 단절은 대기를 취소하고, 종료 후 실패했다면 검증된 실행본을 다시 엽니다. 게시 실패 시 검증한 백업으로 되돌리되 외부 변경이나 재실행이 감지되면 덮어쓰지 않고 보존합니다.
- 준비와 종료 승인은 별도 메시지입니다. 도구는 모든 앱의 준비 응답 뒤 취소 가능한 게시 잠금을 확보하고, 재실행 책임을 기록한 다음 종료 승인을 보냅니다. 다른 앱의 차단 해제를 기다리는 동안 준비된 앱에는 5초마다 대기 갱신을 보냅니다. 준비 후 연결 단절이나 30초 동안 갱신·승인이 없는 경우 현재 앱을 재개합니다. 덮개 준비를 취소해도 전송 중인 유지 요청은 끝나지 않으므로, 상태 전용 조회와 구분해 해제 응답까지 수명을 유지합니다.
- 세션 시작·해제 사유는 사용자 앱의 `application-session.jsonl`에 기록합니다. 루트 서비스의 `session.jsonl`에 있는 `unlocked`만으로는 보안 입력·입력 탭 중단·사용자 요청을 구분할 수 없습니다. 보안 입력과 이벤트 탭 감시 실패에 대한 복구 정책은 업데이트 정책과 독립적으로 유지합니다.
- 세션 기록 쓰기는 별도 큐에서 수행합니다. `occurredAt`은 실제 발생 시각, `at`은 파일 기록 시각이며 진단에는 발생 시각을 사용합니다. 로그 파일 경합이 입력 세션의 메인 하트비트를 막지 않도록 종료 시 대기도 0.2초로 제한합니다.

## 입력과 단축키

CGEvent의 source state와 생성 PID를 기준으로 물리 입력과 프로세스가 만든 입력을 구분합니다. 이 구분은 호환성을 위한 것으로, 보안 인증 수단으로 사용하지 않습니다. 물리 입력은 차단하고 프로세스 입력은 허용하되, 재매핑·가상 HID 도구는 실제 시험으로 확인합니다.

눌림과 해제는 이벤트를 버리기 전에 추적합니다. 차단된 down은 WindowServer 상태에 없을 수 있고, 차단된 up은 캐시에 남을 수 있습니다. 관측한 눌림을 native 캐시만 보고 지우지 않습니다. 필터 시작 전에 복사한 상태는 HID 후보와 출처 불명 상태를 구분합니다. 주입·무관한 해제로 초기 상태를 지우지 않습니다. 일치하는 물리 해제는 HID 후보만 정리하고, 출처 불명 상태는 양쪽 native 테이블의 해제를 확인합니다. HID 정보에도 자동화가 섞일 수 있어 프로세스별 출처를 증명한다고 가정하지 않습니다. 보안 입력·사용자 전환으로 이벤트가 끊겼다면 차단 해제·보안 입력 종료·콘솔 복귀·필터 활성화를 확인한 뒤 다시 읽습니다.

단축키 녹음 중에는 입력 필터와 Carbon 긴급 키를 모두 잠시 중단합니다. 포커스 상실·창 닫기·외부 클릭·Esc에서 취소하며, 녹음한 키가 해제되기 전에는 새 잠금 명령으로 재해석하지 않습니다. 실행한 단축키도 key-up까지 소비합니다. 보조 키를 먼저 놓았을 때의 일반 문자 자동 반복도 통과시키지 않습니다.

긴급 키 교체는 새 등록 성공 후 이전 등록을 해제합니다. 실패하면 기존 키를 보존합니다. 복구에 성공하면 해당 구성 요소의 오류만 지우고, 다른 구성 요소의 오류는 남깁니다. 전원·유휴 방지·화면·세션 오류는 각 구성 요소에서 관리합니다. 복구 여부는 표시 문구 비교로 판단하지 않습니다. 전환 덮개의 대기 시간이 끝나도 현재 화면 복원 응답은 받아 뒤늦은 성공을 반영합니다.

설정은 현재 저장 형식만 읽습니다. 이전 버전 설정을 변환하는 호환 코드는 유지하지 않으며, 현재 값의 손상·충돌 검증은 유지합니다.

유휴 방지 신호는 현재 수정 키 상태를 담은 자체 `flagsChanged` 이벤트입니다. 전송 직전 조건을 확인하고, 필터 도착 시에도 차단 상태·눌림·수정 키 변화가 없는지 다시 검사합니다. 자체 신호로 눌림 추적을 덮어쓰지 않습니다. 세션 탭에서 버렸다고 HID 단계의 상태 변화까지 되돌린다고 가정하지 않습니다. 자동화가 명시적 modifier-down을 보냈다면 명시적 해제 없이 임의로 초기화하지 않습니다.

Spaces 전환에는 일반 제스처 marker와 별도로 비공개 DockControl 이벤트 30이 사용될 수 있습니다. event mask 생성 성공은 실제 제스처 차단의 증거가 아닙니다. macOS와 트랙패드 설정별로 시험합니다. 경로 참고: [iss 구현](https://github.com/joshuarli/iss/blob/master/iss.c), [trackpad companion](https://github.com/scottlamb/macos-trackpad-companion).

## 잠금 전환과 복구

선택한 전원 범위에서는 Mac의 덮개를 닫아도 잠자기로 인해 작업과 Tailscale 원격 접근이 끊기지 않아야 합니다. 입력 차단·화면 끄기·유휴 잠금 예방 흐름을 유지한 상태에서 실제 장비로 확인합니다. 앱의 상태 기록과 외부 장치에서의 실제 Tailscale 접근 성공은 따로 확인합니다.

ChatGPT/Codex의 공식 [Locked use](https://learn.chatgpt.com/docs/computer-use#locked-use)는 실제 macOS 잠금 후의 Computer Use를 위한 추가 기능입니다. 이 기능을 근거로 기존 잠자기 방지 목표나 앱 모드 구성을 자동 변경하지 않습니다. 현재 앱은 macOS 잠금·세션 비활성화에서 전원 유지를 해제하므로, 향후 공식 기능과의 동시 사용을 검토할 때 이 수명 조건을 확인합니다. 설치된 인증 플러그인만으로 기능 활성화·정상 동작을 판단하지 않습니다.

일반 해제는 전환 덮개 준비 응답을 받은 뒤 macOS 잠금을 요청합니다. API 호출 반환·세션 비활성화·보안 입력 시작은 잠금 성공의 증거가 아닙니다. 실제 잠금 관측 후 안정화 대기, 밝기 복원 확인, 덮개 제거 순서를 지킵니다. 요청·상태 조회 API에 걸린 시간을 안정화 대기로 잘못 계산하지 않습니다. 빠른 Touch ID 인증, 요청 마감 직전 잠금, 실패 후 늦은 잠금도 다룹니다.

잠금 플래그가 먼저 바뀌고 인증 화면의 불투명 창이 나중에 나타날 수 있습니다. 시스템 loginwindow 실행 경로를 확인한 뒤, 화면 내용·창 제목 없이 창의 경계·불투명도만 읽어 모든 활성 디스플레이가 가려졌는지 확인합니다. 안정화 시간은 이 표시 확인부터 계산합니다. 전환 덮개는 로그인 애니메이션에서 화면이 축소돼도 가려지도록 화면 밖까지 검은 여백을 두고, WindowServer의 전체 화면 표시를 확인한 뒤 준비 응답을 보냅니다. 이 장비에서 실패한 `CGDisplayFade` 경로는 사용하지 않습니다.

오류 시 재시도 안내와 긴급 해제를 유지합니다. 긴급 해제·시험 만료·감시 중단·응답 지연은 복구 우선 경로이며 macOS 인증 전환을 요구하지 않습니다. 이미 잠긴 OS 인증을 우회하지 않습니다. AppKit 창의 `isVisible`이나 덮개 ACK만으로 compositor가 인증 화면을 완성했다고 보장할 수 없으므로 실제 화면 확인이 필요합니다.

비동기 명령은 세션 세대와 작업 ID로 구분합니다. 이전 시험 만료·덮개 fade 완료·밝기 복원 응답이 새 세션을 해제하지 못하게 합니다. 사용자가 긴급 해제를 누르면, 직전에 대기 중이던 잠금 명령이 있더라도 처리합니다.

처음 밝기를 낮추기 전에 읽은 값을 복원할 원래 밝기로 보관합니다. 밝기 전환 도중 방향이 바뀌거나 실패 후 다시 잠글 때도 중간 값을 원래 밝기로 덮어쓰지 않습니다. 저장된 원래 값이 존재한다는 사실만으로 현재 화면이 어둡다고 판단하지 않습니다. 밝기 API 실패와 복원 실패는 구분해 알립니다.

밝기 보조 프로세스는 내장·Apple 화면의 DisplayServices와 Apple Silicon 외장의 DDC/CI 통신을 함께 담당합니다. 외장은 밝기 기능(0x10)만 사용하며 화면 연결·전원·입력 소스를 바꾸지 않습니다. 응답의 주소·길이·기능·결과·체크섬·범위를 확인하고, 최종 밝기와 복원 값은 재조회합니다. 하드웨어 통신은 메인 입력 루프에서 하지 않으며 외장 유지 조회는 2초 간격으로 제한합니다. 근거: [m1ddc](https://github.com/waydabber/m1ddc), [MonitorControl의 Apple Silicon 통신](https://github.com/MonitorControl/MonitorControl/blob/main/MonitorControl/Support/Arm64DDC.swift).

Apple Silicon의 AV 서비스는 framebuffer shim의 자식이라고 가정하지 않습니다. CoreDisplay 경로로 얻은 registry ID를 IOService 순회에서 찾아 해당 framebuffer 구간의 외장 proxy 하나만 연결합니다. 경로가 없거나 후보가 여럿이면 추측해 다른 화면에 쓰지 않습니다.

원래 밝기는 쓰기 전에 사용자 영역 복구 파일에 기록합니다. CGDisplayID는 재연결 때 달라지거나 다른 화면에 재사용될 수 있으므로 CoreDisplay UUID로 대상을 식별하고, 없는 화면의 복구 값을 버리지 않습니다. 차단 중 추가된 화면도 원래 밝기·감마를 보존한 뒤 어둡게 합니다. 유지 중 제어 실패를 앱에 전달하고, 감마 확인은 DDC 조회 간격을 기다리지 않습니다. 정상 복원을 확인한 항목만 기록에서 지우며 하트비트가 살아 있는 동안 재연결 복원을 재시도합니다. 파일 없음과 기존 기록의 읽기·디코딩·항목 검증 실패를 구분합니다. 읽지 못한 원래 값은 복원 성공으로 처리하거나 현재 밝기·검은 감마로 교체하지 않으며, 오류가 해소될 때까지 새 변경을 막고 명시적 복원에서 다시 읽습니다. 유효한 빈 기록은 복원 시 제거하고 제거 실패도 미복구 상태로 유지합니다. 앱 시작 때 남은 기록을 복구하며, 프로세스 시작 직후의 종료도 실패로 처리해 최대 세 번 시도하고 미복구 상태를 알립니다. 동시에 두 밝기 보조 프로세스가 같은 기록을 소유하지 않도록 파일 잠금을 유지하고 잠금 파일의 inode를 삭제하지 않습니다.

밝기 보조 프로세스 자체의 충돌·강제 종료에서는 마지막 복원 루프가 실행되지 않습니다. 부모는 입력·전환 덮개를 정리한 뒤 남은 기록을 새 복구 프로세스에 인계합니다. 복원 전송 실패 뒤 늦게 도착한 종료 알림도 같은 복구 시도로 취급해 세 번의 상한을 초기화하지 않습니다. 새 차단 세션에서만 시도 횟수를 초기화하며, 앱 종료·재시작 중에는 복구 프로세스를 새로 시작하지 않습니다.

DDC 밝기 0은 백라이트의 최솟값이므로 외장 화면의 작업 내용이 남을 수 있습니다. 지원 외장은 같은 밝기 보조 프로세스의 `ExternalBlackout`이 원래 RGB 감마 테이블을 저장한 뒤 전환 비율에 맞춰 0까지 낮춥니다. 내장 감마·색상 프로필·화면 연결·포커스는 변경하지 않습니다. 테이블 복원을 재조회해 확인한 뒤에만 복구 기록과 인증 전환 덮개를 해제합니다. 색상 프로필로 일괄 초기화하지 않고 각 화면의 원래 테이블을 그대로 복원하며, 감마 기록만 남은 재시작도 복구합니다. `CGSetDisplayTransferByTable` 성공과 물리 화면·자동화 캡처 결과는 별도로 확인합니다. 검정 오버레이는 캡처에 섞일 수 있어 차단 중 화면 숨김에 사용하지 않습니다. 근거: [Apple 감마 테이블 API](https://developer.apple.com/documentation/coregraphics/cgsetdisplaytransferbytable(_:_:_:_:_:)), [MonitorControl의 소프트웨어 밝기](https://github.com/MonitorControl/MonitorControl/blob/main/MonitorControl/Model/Display.swift).

## 전원과 유휴 시간

전원 assertion은 입력 차단·옵션 활성·선택한 전원 범위에 묶습니다. 배터리 사용은 덮개 유지의 별도 선택 옵션이며 기본은 꺼짐입니다. 일부 생성·갱신에 실패하면 전체를 정리하고 재시도할 수 있게 합니다. 메인 스레드가 멈춰도 방지가 영구히 남지 않도록 유효 시간이 있는 assertion을 갱신합니다. 프로세스 종료 정리만으로 살아 있는 앱의 응답 중단까지 처리됐다고 보지 않습니다.

전원 assertion만으로 세션 유휴 시간이 초기화된다고 가정하지 않습니다. 신호 전송 후 HID 유휴 시간 감소를 확인하고 실제 macOS 잠금은 별도로 관측합니다. 눌린 입력·권한 없음·보안 입력·다른 세션·실제 잠금·화면 보호기·화면 잠자기 동안은 중단합니다. 전원 assertion 만료와 갱신은 [Apple IOPMLib.h](https://github.com/apple-oss-distributions/IOKitUser/blob/main/pwr_mgt.subproj/IOPMLib.h), 이벤트 상태 테이블은 [Apple CGEventSourceStateID](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid)를 참고합니다.

일반 assertion은 덮개 잠자기를 보장하지 않으며, `AppliesOnLidClose`는 Apple 전용 권한을 검사합니다. 비공개 `kPMSetClamshellSleepState`는 powerd와 같은 전역 비트를 변경하고 연결 종료 시 되돌리지 않으므로 앱별 lease로 취급하지 않습니다. 덮개 모드는 `pmset disablesleep`을 사용합니다. 일반 잠자기도 제한하므로 허용된 전원 범위·일반 차단 세션에 묶고 기존 전역 금지 설정은 덮어쓰지 않습니다. 저장 설정과 커널 상태를 모두 읽어 활성화·복구를 확인합니다. 근거: [Apple 전원 권한 검사](https://github.com/apple-oss-distributions/PowerManagement/blob/main/pmconfigd/PMAssertions.c), [RootDomainUserClient](https://github.com/apple-oss-distributions/xnu/blob/main/iokit/Kernel/RootDomainUserClient.cpp), [pmset 구현](https://github.com/apple-oss-distributions/PowerManagement/blob/main/pmset/pmset.m).

고정 24시간 상한은 장시간 작업 중 차단·유휴 잠금 방지까지 종료시켜 실제 자동 잠금으로 이어졌습니다. 유지 시간은 사용자가 선택하며 기본은 무제한입니다. 서비스는 필수 IPC 필드의 숫자·범위를 확인하고 최초 활성화 때만 기간을 고정합니다. 하트비트가 마감 시각을 연장하거나 중간에 다른 기간으로 바꾸지 않습니다. 시간 만료는 일반 해제의 인증 전환을 따르고, 허용하지 않은 전원 분리·배터리 잔량 제한·응답 중단은 기존 복구 경로를 유지합니다. 무제한에도 응답 lease·독립 watchdog·복구 기록을 적용합니다.

`AppDelegate`는 사용자의 덮개 모드 요청을 관리합니다. `LidSleepController`는 메인 루프의 하트비트와 보조 도구 설치·연결을, `LidService`는 전원 제어 권한을 담당합니다. 설치할 때만 관리자 승인을 받고 root 소유 앱·LaunchDaemon을 배치합니다. 로컬 소켓에서 사용자 UID·서명 식별자·승인한 인증서의 정확한 지문을 검증하며, IPC는 상태·하트비트만 받습니다. 앱 전체의 CDHash를 고정하면 UI 수정마다 관리자 재승인이 필요하므로 업데이트 식별에 사용하지 않습니다. 기본 빌드는 사용자 키체인의 지속적인 코드 서명 신원을 사용하며 별도 시스템 신뢰 설정은 추가하지 않습니다. 명시적인 ad-hoc 빌드만 CDHash에 고정됩니다. 설치 시 요청한 실행 중 앱은 여전히 원본의 CDHash와 대조합니다. 설치·업데이트·제거는 접근 권한 화면에서만 요청하며, 설정에서 기능을 켰는데 준비가 필요하면 그 화면으로 안내합니다. 보조 도구 설치·업데이트가 사용 옵션을 임의로 켜지 않습니다.

`Tools/PowerService`는 UI 없이 전원 서비스와 watchdog만 실행하는 별도 바이너리입니다. 필요한 전원 소스를 직접 공유해 복제하지 않으며 앱 버전·UI는 보조 도구에 포함하지 않습니다. 설치 상태는 보조 도구 CDHash·IPC 버전·클라이언트 인증 요구식·사용자 UID로 비교합니다. 앱 버전만으로 갱신을 요구하지 않습니다. 보조 도구가 실제로 바뀌거나 서명 신원이 바뀌면 재승인을 요구합니다. 인증 요구식은 이름이나 경로만으로 완화하지 않습니다. 설치 때는 앱 전체를 root 전용 임시 영역에 복사해 실행 중 앱의 CDHash와 중첩 서명을 검증한 뒤, 그 안의 보조 도구만 추출·배치합니다. 승인 중 사용자 영역 원본이 교체되는 경쟁을 피합니다. 중첩 코드는 표준 `Contents/Helpers` 경로에 두어 일반 리소스로 이중 봉인하지 않습니다.

서비스와 독립 watchdog은 같은 flock을 공유하되 서로 다른 프로세스 그룹에 둡니다. 감시 대상이 죽거나 멈추면 먼저 그 그룹의 미완료 명령까지 종료하고 복구합니다. 감시 프로세스가 먼저 죽거나 파이프가 먼저 닫혀도 서비스가 직접 복구합니다. 전원 변경 전에 원래 정책의 복구 기록을 저장·동기화하며, launchd 재시작·부팅 때 남은 기록을 복구합니다. 기록이 없거나 유효하지 않으면 다른 정책을 임의로 초기화하지 않습니다. flock 파일을 삭제해 새 inode의 동시 소유자가 생기게 하지 않습니다. 진단 journal은 비차단 flock을 사용해 경합한 기록을 건너뛰고, 전원 복구 요청·실행·재시도는 진단보다 먼저 진행합니다. 복구 원인과 재시도 오류는 완료 후 남깁니다.

설치·제거는 복구 lease와 별도의 root 소유 영속 설치 잠금으로 기존 설정 검증·백업부터 commit·rollback·stage 정리까지 직렬화합니다. 잠금 파일의 소유자·종류·쓰기 권한을 확인하고, 대기 만료 시 서비스 변경 전에 중단합니다. O_CLOEXEC로 자식 도구에 잠금이 남지 않게 하며 inode를 삭제하지 않습니다. 기존 설정의 실제 부재만 백업 없음으로 취급하고 읽기 오류는 unload 전에 전파합니다. 설치·제거의 변경 트랜잭션은 서비스를 중단한 뒤 복구 잠금·receipt를 확인하는 단계부터 실패 복귀를 소유합니다. 기존 helper 백업과 새 helper 게시가 실제로 끝났는지 각각 추적해 첫 이동 실패 시 원본을 삭제하지 않습니다. 이전 job을 다시 등록하더라도 잘못된 receipt 자체를 안전한 기록으로 간주하지 않으며, 복원이 실패한 원본과 stage를 보존합니다. 테스트는 인증 이후의 같은 트랜잭션에 임시 경로·가짜 launchctl·전원·rename 경계만 주입합니다.

부모 실행 파일의 경로를 비교할 때는 양쪽 심볼릭 링크를 해석합니다. macOS의 `proc_pidpath`와 Foundation은 같은 `/private/tmp` 경로를 `/tmp`로 다르게 표현할 수 있습니다.

시스템 daemon은 GUI 세션이 없으므로 WindowServer의 세션·디스플레이 정보를 직접 읽는다고 가정하지 않습니다. 서명을 확인한 앱이 자기 세션 상태를 보내고, daemon은 콘솔 UID와 실제 전원·배터리 잔량·커널 상태를 별도로 확인합니다. 앱의 하트비트는 메인 루프에서만 보냅니다. 앱이 멈췄을 때 연결 스레드가 대신 갱신하지 않습니다. 준비 응답 전에 입력 차단·밝기 변경을 시작하지 않고, 세션 ID로 늦은 응답과 빠른 재차단을 구분합니다. `Tests/check_lid_service.py`는 네이티브 IPC·종료·응답 중단·부분 적용·늦은 자식 명령·재시작 복구를 파일 기반 가짜 전원으로 검사합니다.

단축키로 시작한 준비 요청은 주기적인 상태 확인의 전송 간격을 기다리지 않습니다. 이전 heartbeat가 이미 진행 중이면 그 응답 직후 현재 세션 조건으로 준비 요청을 보냅니다. 준비 완료와 실패는 모두 보낸 요청의 세션이 현재 준비와 일치할 때만 전달합니다. 초기 활성화가 거절되면 응답의 활성 세션은 비어 있거나 이전 값일 수 있으므로, 실패의 소유자를 응답 세션으로 판단하지 않습니다.

배터리 사용 여부와 종료 잔량은 세션 시작 때 고정하며 하트비트로 확대하지 않습니다. 앱과 서비스는 같은 전원 정책을 사용하고, 서비스는 클라이언트가 보고한 전원·잔량을 신뢰하지 않습니다. 내장 배터리의 현재 용량/최대 용량을 IOPS에서 읽어 선택한 종료 기준 이하 또는 조회 실패 시 잠자기 정책을 복구합니다. 종료 기준은 10~80%의 5% 단위이며 기본은 10%입니다. 설정 저장과 IPC에서 숫자·범위를 검사하며 잘못된 IPC는 적용하지 않습니다. 이 잔량 제한은 무제한 시간 설정에도 적용되며 UI에 표시합니다. 외부 전원 연결·분리로 세션 ID나 시작 시각을 바꾸지 않습니다. 근거: [Apple 배터리 용량](https://developer.apple.com/documentation/iokit/kiopscurrentcapacitykey), [전원 assertion의 저전력·열 한계](https://developer.apple.com/documentation/iokit/kiopmassertiontypepreventsystemsleep).

저장된 전원 정책은 `pmset`과 같은 `IOPMCopySystemPowerSettings` 읽기 API로 조회해 준비 과정의 반복 명령 실행을 줄입니다. 변경은 기존의 고정된 `pmset -a disablesleep 0/1` 경로를 사용하며 저장값·커널 적용 확인과 복구 절차를 유지합니다.

외부 모니터 없이 덮개를 닫은 단기 실기에서는 프로세스·입력 필터·내장 디스플레이 연결이 유지됐고 시험 만료 시 전원 정책이 복구됐습니다. 화면 연결 정보만으로 캡처·클릭·문자 입력 성공까지 판단하지 않습니다. 가상 화면은 실제 화면이 사라지는 경우에만 검토합니다. 유휴 신호 전송 후 HID 유휴 시간은 감소해도 combined-session 시간은 계속 증가할 수 있습니다. 검증 수치와 실패 표시를 해석할 때 측정 대상의 차이와 실제 macOS 잠금 발생을 함께 확인해야 합니다.

## 권한·화면·배포

손쉬운 사용 허용과 실제 event tap 준비는 별도 상태입니다. 상태창·아이콘·메뉴가 같은 준비 상태를 표시하도록 변화 시 갱신합니다. 허용 요청 시스템 팝업을 반복 생성하지 않고 기존 시스템 설정 화면을 엽니다.

진단 상태는 메인 스레드에서 수집하고 `DiagnosticsWriter`의 직렬 큐에서 원자적으로 저장합니다. 쓰기가 밀리면 대기열에는 가장 최근 상태 하나만 남깁니다. 저장 성공·실패 결과는 메인 스레드로 전달합니다. 디스크 대기가 입력 heartbeat를 지연하지 않으며, 실패한 저장을 성공으로 캐시하지 않습니다.

실제 앱의 PID·경로·버전·갱신 시각을 확인합니다. 터미널 진단은 터미널 권한을 물려받을 수 있고, 종료된 앱의 JSON은 과거 기록입니다. 서명 신원 전환이나 명시적인 ad-hoc 빌드에서는 정확한 앱을 다시 등록해야 할 수 있습니다. 동일 이름의 옛 앱과 미리보기를 배포 폴더에 쌓지 않습니다.

설정 창은 작은 화면의 사용 가능 높이에 맞추고 본문을 스크롤합니다. 접힘 영역·정상 권한·권한 없음·필터 실패·라이트/다크 화면을 미리보기에서 확인합니다. 접근성 트리만 읽었다면 시각적 배치까지 검증했다고 기록하지 않습니다. 메뉴 초기화만 검사하면 설정 창 생성 중 constraint 예외를 놓칠 수 있으므로 실제 설정 창을 한 번은 열어봅니다.

배포 대상에 파일을 직접 덮어쓴 뒤 서명하지 않습니다. 같은 파일시스템의 임시 앱을 조립·서명·검증한 뒤 교체합니다. 교체 실패 시 이전 앱을 복원하고, 복원까지 실패하면 이전 앱 경로를 보존해 알립니다. 배포·복원은 대상이 이미 존재하면 실패하는 rename을 사용해 동시 빌드가 앱 안에 앱을 중첩하지 못하게 합니다.

## 검증 기준

정상 값 저장·구현의 분기 반복·겹치는 fixture를 늘리지 않습니다. 입력과 자동화 분리, 긴급 복구, 오래된 응답 무시, 실제 잠금 확인, 밝기 원래 값 보존, 전원 수명처럼 고장 시 사용자에게 영향이 있는 계약을 남깁니다. 한 복구 원인이 다른 복구 원인 때문에 우연히 통과하지 않도록 시간 조건도 분리합니다.

부품 검사 통과와 `AppDelegate`의 조율 검증을 구분합니다. 정상 해제부터 긴급 중단·늦은 응답·보조 프로세스 종료·복구 상한까지 실제 조율 메서드를 함께 확인합니다. OS 경계를 모의 객체로 대체한 격리 실행에서는 원본 메서드 본문을 유지했는지 확인하고, 그 결과를 물리 화면·입력·전원 시험으로 표현하지 않습니다.

보조 프로세스 headless 검사는 IPC·응답 중단·EOF·재시도·오래된 명령 무시를 확인합니다. 창을 띄우지 않는 검사로 화면이 계속 가려진다고 판단하지 않습니다. 실제 물리 제스처·단축키·잠금 중 자동화·macOS 인증 전환은 장비에서 확인합니다.

검사 후 날짜별 로그·이전 소스 복사본·시험 앱·중복 백업은 정리합니다. 다음 수정에 필요한 원인과 제약은 이 메모에 합치고 수치·PID·시간별 작업 일기는 남기지 않습니다.

DMG는 서명된 앱을 그대로 복사하고 창 배치·배경은 볼륨의 `.DS_Store`에 저장합니다. 앱 자체에 `SetFile`의 확장자 숨김 플래그를 붙이면 FinderInfo가 생겨 엄격한 서명 검증을 통과하지 못합니다. 한글 파일명은 HFS+의 NFD 형식과 `.DS_Store` 키를 맞춰 아이콘 배치가 무시되지 않도록 합니다. 패키징 스크립트는 최종 이미지를 읽기 전용으로 마운트해 앱 서명·실행 파일·응용 프로그램 바로가기를 검증한 뒤 게시하며, 마운트 해제 실패 시 작업 영역을 보존합니다.

설치 시작부터 실행 인계와 디스크 정리까지는 `InstallationFlow`가 담당합니다. DMG 안에서 시작한 프로세스는 입력 필터·복구·전원 제어를 시작하지 않고 설치된 앱으로 실행을 넘깁니다. Finder에서 복사를 마쳐도 앱이 자동 실행되지는 않습니다. 디스크 정리 안내는 응용 프로그램에서 앱을 처음 열 때 표시합니다. 마운트 목록과 엄격한 앱 서명으로 같은 빌드의 디스크를 찾고, 후보가 여러 개면 추측하지 않습니다. 추출은 강제하지 않으며 실패하면 DMG를 그대로 둡니다. 파일 정리는 별도 동의를 받고 휴지통을 사용하며, 확인창 이후 다른 볼륨·파일로 교체되지 않았는지 UUID와 파일 식별값을 다시 검사합니다.

### 비정상 해제의 시각적 가림

`AppDelegate`가 `PrivacyShield`와 별도의 밝기 복원 대기 플래그를 소유합니다. 활성 차단 세션의 명시적 health-failure 원인만 latch를 만들며, 정상 종료·긴급 해제·시험 종료·전환이 완료된 macOS 잠금에는 만들지 않습니다. 기존 `DisplayTransitionCover`의 응답·타이머·자동 해제와 수명을 공유하지 않습니다. 현재 모든 NSScreen에 불투명 창이 표시됐는지 확인한 뒤 앱의 밝기 복원을 진행합니다. 확인 실패 시 최대 2초 뒤 원래 복구 흐름을 재개하고 가림 상태와 오류는 유지합니다. 화면 재연결 시 새 패널을 만든 뒤 기존 패널을 치우며, 이전 세션 타이머는 generation으로 거릅니다. 가림 표면 인터페이스에는 공개 해제 콜백을 두지 않습니다.

비정상 해제 뒤 보안 입력이 끝나거나 macOS 세션이 돌아오는 것만으로 가림을 해제하지 않습니다. 긴급 해제·명시적 복구 명령·메뉴의 가림 해제 또는 명시적 앱 종료만 해제합니다. 공개 가림 화면에는 화면 가림 아이콘·제목·유지 설명을 중앙에 표시하며, 버튼·단축키·오류 사유를 노출하지 않습니다. 새 차단·개별 화면 조작·단축키 녹화·재시작·업데이트는 가림 해제 후 가능합니다. 부모 앱이 멎거나 죽으면 독립 밝기 guardian은 계속 기존 안전 복원을 수행하므로, 이 가림은 보안 경계나 무노출 보장이 아닙니다. `Tools/PrivacyShieldPreview`는 실제 content view만 640/320px 일반 창에서 검사하며 전체 화면·입력·전원 backend를 포함하지 않습니다.

`--reveal-screen`은 AppDelegate·입력·화면·전원 제어를 초기화하지 않는 CLI입니다. 같은 사용자·서명 식별자의 실행 완료 앱 하나를 찾고, 로컬 소켓의 커널 제공 peer PID/UID와 승인한 서명을 검증합니다. 두 설치 경로(/Applications와 dist)는 같은 서명을 공유하므로 실행 경로의 문자열 일치는 요구하지 않습니다. 같은 번들로 등록된 화면 보조 프로세스는 실제 서명·커널 peer가 확인되는 main control endpoint가 없으면 제외합니다. 대상 탐색 연결에서는 명령을 보내지 않으며, 하나로 결정된 대상과 다시 신원을 확인한 연결에서만 복구를 요청합니다. 기존 `DeferredUpdateGate`의 별도 요청 분기로 전달하며 서버도 커널 peer PID/UID와 앱 서명을 검증합니다. 일반 Python 업데이터의 승인과 recovery fd를 공유하지 않아 업데이트 대기 중에도 복구할 수 있습니다. 경로·실행 명령·권한 변경을 입력으로 받지 않습니다. AppDelegate는 가림 활성·입력 차단 해제·인증 전환 없음 조건을 확인한 뒤 기존 긴급 복구 흐름을 실행합니다. 서버는 별도 fd/generation과 2초 main 실행 lease·연결 생존 확인을 적용하고, 클라이언트의 전체 소켓 IO는 3초의 단조 시각 제한을 사용합니다. 늦은 요청·종료 후 콜백은 가림 해제를 수행하지 않습니다.

`Tools/PrivacyRecoveryProbe`는 별도 식별자의 앱과 다른 서명 클라이언트로 실제 인증·거부·응답·업데이터 대기 병행을 검사하며 운영 AppDelegate·입력·화면·전원 backend를 링크하지 않습니다. 기존 UpdateGateProbe는 독립적인 deny-all recovery 인증 stub을 사용해 기존 headless updater 검사의 범위를 유지합니다.

### 입력 해제 전달과 종료 실패 복귀

입력 스레드가 먼저 차단을 해제한 원인은 `InputFilterSnapshot.releasedBy`에 같은 mutex로 보존합니다. 다음 main tick은 이를 먼저 처리해 대기 중인 정상·긴급·시험 해제를 오류 해제로 바꾸지 않습니다. 이후 health 신호는 첫 원인을 덮어쓰지 않고 새 긴급 해제만 우선하며, 새 configure/stop에서 원인을 비웁니다. 재시작·업데이트 준비가 실패하면 닫히는 helper의 종료를 기다린 다음 미복구 기록을 기존 시도 횟수·backoff 그대로 다시 소유합니다.

밝기 및 감마의 read/save/write 사이에 디스플레이가 바뀔 수 있으므로 native 쓰기와 gamma 변경 직전에도 고유한 현재 UUID→ID 연결을 확인합니다. 불일치하면 다른 화면에 쓰지 않고 원래 화면의 복구 기록을 유지합니다. 보조 도구 준비를 즉시 재시도할 때는 이전 scope의 requested:false 응답을 먼저 확인하며 helper 실행 파일과 통신 규약은 바꾸지 않습니다. 업데이트 commit이 main queue에서 5초 넘게 지연되면 종료 권한을 폐기하고 현재 앱을 재개합니다.

`Tests/check_app_lifecycle.py`는 현재 App.swift의 원본 lock·tick·unlock·cover/밝기 응답·macOS 잠금 결과·복원·실패 복귀 메서드를 추출해 그대로 컴파일합니다. 정상 시작에서 cover ACK·인증 확인·밝기 ACK·cover 해제까지 연결하고 잠금 실패·복원 재시도·오래된 ACK도 검사합니다. 원본 App 초기화와 native surface는 링크하지 않으며, event-tap 준비·창·밝기·전원·설치 경계는 가짜 객체입니다. 입력 이벤트는 메모리에서만 구성해 filter에 직접 전달하고 시스템에 post하지 않습니다. guardian fixture는 실제 밝기 backend 없이 메모리 값을 먼저 낮춘 뒤 EOF·heartbeat 만료·닫힌 응답 파이프에서 원래 값으로 복원되는지 stderr 기록으로 검사합니다.

인증 전환 중의 logical locked 플래그만으로는 기존 덮개를 제거하지 않습니다. 밝기 guardian 종료 등으로 차단을 해제해야 한다면 별도 privacy surface를 먼저 띄우고 실제 표시 확인 후 기존 덮개를 인계합니다. 새 표면 표시가 실패해도 밝기 복원 지연은 2초에서 끝내되 건강한 기존 덮개는 명시적 해제 또는 실제 새 표면 확인까지 유지합니다. 가림 content는 화면의 정해진 크기에 고정해 label의 intrinsic size가 패널을 축소하지 못하게 하고, 미리보기는 요청 크기와 실제 content bounds가 640/320px로 일치하는지도 검사합니다.

외장 밝기 smoke 도구는 오래된 진단 JSON을 차단 여부의 근거로 삼지 않습니다. 실제 운영 앱 프로세스가 하나라도 있으면 거부하며, 공유 brightness lease를 얻고 미복구 기록이 없음을 확인한 뒤에만 최초 밝기를 읽습니다. 동시 smoke가 다른 smoke의 임시 밝기를 원래 값으로 저장하지 못하게 합니다. `SOFTLOCK_PROBE_GUARD_ONLY` 빌드는 프로세스 guard만 포함하고 디스플레이 backend를 링크하지 않아 실행 중 앱 거부를 안전하게 확인할 수 있습니다.

앱 자체 재시작은 Launch Services의 실행 성공 응답만으로 기존 앱을 종료하지 않습니다. `RelaunchHandoff`의 사용자 소유 0700 임시 디렉터리에서 일회용 UUID ticket을 교환하고, 기존·새 프로세스의 UID·서명 요구식·실행 경로·프로세스 시작 시각을 확인합니다. 새 앱은 준비 응답 후 기존 프로세스의 실제 종료를 기다리며, 그 뒤에도 `InstallationFlow`의 일반 중복 실행 검사를 거쳐야 입력·전원 제어를 시작합니다. 준비 확인이 15초 안에 오지 않으면 기존 앱이 ticket을 폐기하고 복귀합니다. 자식에게 별도 시간 만료를 두지 않아 기존 앱의 종료 결정과 경합하지 않습니다. `Tools/RelaunchProbe`는 별도 식별자의 일반 앱에서 실제 NSWorkspace 인계와 원본 InstallationFlow를 실행하며 운영 앱·입력·밝기·덮개·전원 backend를 실행하지 않습니다.

재시작의 15초 제한은 Launch Services 호출 전에 시작해 실행 확인창·승인창이 완료 콜백을 지연하는 시간도 포함합니다. 만료 뒤 늦은 콜백은 ticket identity로 무시합니다. 일반 중복 실행 검사는 NSWorkspace의 main-loop 단위 snapshot만 믿지 않고 `kill(pid, 0)`이 ESRCH를 반환한 종료 항목만 제외하며, 권한·조회 실패는 기존 실행본으로 보수적으로 유지합니다. 원본 App의 실행 메서드와 원본 InstallationFlow의 peer 필터를 fake Launch Services 경계에 연결한 테스트가 이 두 경합과 성공·실패 인계를 검사합니다.


## 언어 지원

영어·한국어를 지원하며, 기본값은 macOS의 앱별 언어 설정을 따릅니다. 앱 설정에서 영어 또는 한국어를 선택하면 `interfaceLanguage`에 저장하고, ‘macOS 설정 따르기’를 선택하면 이 키를 제거합니다. `AppleLanguages` 등 macOS 설정은 덮어쓰지 않습니다. 선택만으로 저장하거나 재시작하지 않으며 ‘적용 및 재시작’을 눌러야 반영됩니다. 차단·화면 복구·가림·단축키 녹화·업데이트·보조 도구 정리 중에는 적용을 막고, 기존 재시작 인계 절차를 사용합니다.

표시 문구는 `Localization/Localizable.xcstrings`에서 관리합니다. 상태 코드·IPC·저장된 설정값에는 번역을 적용하지 않습니다. 잠금 전환 실패 원인은 안내 문구와 분리하여 전달합니다. 카탈로그 수정 후 Xcode 15 이상의 `xcstringstool`로 `python3 Tools/localize.py`를 실행하고, 생성된 `Sources/Resources/{en,ko}.lproj`도 함께 반영합니다. 일반 빌드는 이 파일을 사용하므로 카탈로그 컴파일 도구가 추가로 필요하지 않습니다. SwiftPM은 모듈 번들을, 패키징한 앱과 UI 미리보기는 각 앱 번들의 리소스를 사용합니다.

`python3 Tools/localize.py --check`로 생성 파일 일치를 확인하고, `python3 Tests/check_localization.py`로 번역 누락과 Foundation의 영어·한국어·대체 언어 선택, 앱 내부 언어 우선순위, 인자·퍼센트·줄바꿈을 검증합니다. 이 검사는 AppKit·입력 차단·밝기·전원 기능을 실행하지 않습니다.

앱 표시 문구만 바뀌는 로컬 업데이트에서는 `SOFTLOCK_POWER_HELPER_PATH`로 검증된 기존 `SoftLockPower.app`을 지정해 보조 도구 승인을 유지할 수 있습니다. 이 경로는 앱 빌드에만 적용하며, 재사용한 도구는 다시 서명하지 않습니다. 최종 후보는 기존 서명·보조 도구 해시·프로토콜 검사를 그대로 통과해야 합니다. 보조 도구 동작이 바뀌는 릴리스에는 이 옵션을 사용하지 않습니다.

## 설정 화면과 상태 표시

설정 창은 일반·작업 유지·권한 및 보조 도구·테스트 및 진단의 네 페이지로 구성합니다. 배터리 사용·종료 기준은 덮개 유지의 하위 설정이며 비활성화해도 값과 위치를 보존합니다. 권한 페이지의 입력 테스트 연결은 손쉬운 사용 카드 안의 보조 링크입니다. 짧은 입력 테스트는 화면 밝기·덮개 유지 검증을 포함하지 않습니다.

사이드바에는 페이지 탐색만 두고 세션 상태는 테스트 및 진단 본문에서 확인합니다. 긴 오류는 본문 하단에 표시하고, 팝오버 헤더에는 앱 이름과 연결 수만 표시합니다. 입력 표시는 세션 의도와 실제 입력 감시 연결·차단 스냅샷을 함께 확인합니다. 잠자기 방지는 활성 요청·설정 비활성·차단 시작 대기·중단을 구분합니다. 모니터 상태는 macOS 출력·밝기 관측이며 물리 전원 확인이 아닙니다.

`Tools/DesignPreview`의 `--settings-pane general|work|permissions|diagnostics`, `--small`, `--settings-audit <JSON 경로>`로 페이지 배치와 이동·의존 옵션을 검사할 수 있습니다. 미리보기는 운영 앱의 입력·밝기·전원 제어를 실행하지 않습니다.
